# 商品二创：文案替换、提示词与参考生视频

入口：项目 → 视频二创 → 选择参考视频并分析 → 下一步：台词与花字替换。

页面现分为参考分镜、台词/花字替换、视频制作三个独立步骤，顶部可点击切换；生成、保存、返回和下一步集中在顶部固定工具栏。第二步进入即显示原片已提取台词和后期花字；成片时长固定为原片时长向上取整（18.773秒→19秒），后端同步校验，旧15秒稿需重新生成。第三步同时提供提示词生成/编辑保存、视频生成与历史版本，每版保留自己的提示词快照；有运行或结果未知的任务时禁止重复提交。提示词上方展示按提交顺序排列的商品参考图片，可点击放大。

新增 PUT `/prompt` 保存用户编辑的提示词、GET `/renders` 查询该改编稿的历史视频。手改提示词不触发模型调用；再次生成视频需要费用确认。提示词生成使用两次串行请求（商品使用方式/差异，之后完整出片正文），不等于正在生成视频。网络超时与连接中断现在分别显示，不再只给笼统格式错误；历史错误没有完整诊断日志，不能反推其确切网络原因。

## 已实现

- 只能使用当前项目绑定的商品，读取其全部图片和已保存的商品分析，包括用户修改。商品只有一个时自动选中。
- 生成替换文案时，模型判断参考商品与目标商品的品类、用途、使用动作是否兼容；返回判断依据和改编方向。跨品类保留节奏/拍法，按目标商品重建动作；无法判断标待核对。判断仍需用户核对，不是确定性品类检测。
- 台词以原文和替换稿对照，用户可改或留空表示不使用。花字总开关默认关闭；开启后生成原片后期花字的对应替换，每条还可勾选。产品实物印字不读、不展示、不转为花字。
- 用户确认保存文案后才能生成视频提示词。改文案、时长或花字开关将清空旧提示词；商品图片/分析、参考分镜变化将旧稿标过期。
- 出片正文由参考模块的第三段提示词生成，服务端检查镜数顺序、确认台词只出现一次、已勾选花字出现、长度不超过5000字符；不过时失败并保留文案，不自动提交视频。目标时长4–30秒，固定9:16，清晰度可选480p/720p/1080p，默认480p。
- 电商短视频模块的三段原始提示词已按源码静态字符串提取为 `backend/src/main/resources/prompts/ad-remake-copy.txt`、`ad-remake-use.txt`、`ad-remake-body.txt`。来源为 `G:/manjupingtai/mj_system/manjupingtai2/backend/app/prompts/zh/ad_remake_write_prompt.py` 的三个同名阶段常量，正文包含原模块共享的品牌、商品保真和音乐规则。原文资源不改动；末尾追加本项目字段映射、跨品类、固定竖屏、忽略产品印字及花字开关等必要适配。
- 调用顺序先照原模块：替换台词/花字 → 商品使用方式卡与逐镜差异 → 出片纯正文。当前先建立可运行基线，不把原项目历史经验当成已在本项目验证的效果保证；后续再按用户验收优化。
- 最后确认才创建作品和VIDEO_API产单并进入现有生成队列；重复同revision请求被拒绝。点击前两个生成按钮只调用文案模型，不生成视频。
- 文案任务异步落库，显示实际阶段；失败不自动重发，旧文案保留。旧结果有独立来源快照，重新生成失败不会把旧文案伪装为新来源结果。

## 接口

前缀 `/api/clients/{client}/campaigns/{campaign}/remake/{asset}/{anchor}`：

- GET：当前稿、revision、任务状态、stale、prompt。
- POST `/copy`：`{revision,confirmed:true,overlays:false,duration:15}`。
- PUT：`{revision,draft}`；服务端锁定原句、原时间段、来源ID，用户只改自己的文案和勾选状态。
- POST `/prompt`：已确认文案 → 视频提示词；费用单独确认。
- POST `/render`：`{revision,confirmed:true,resolution:"480p"}` → `{projectId,job}`。

V7迁移新增 `remake_drafts`；主键id，唯一关系为客户/项目/参考视频/商品。已有商品改编稿的参考视频禁止直接删除，以保留引用。

## 重新进入视频二创（2026-11-13）

- 选择参考视频后，URL 带 reference，并按客户与项目记录上次选择。重新进入时，若 URL 未指定视频，先恢复仍存在的上次选择；仅有一条参考视频时自动选中。切换其他视频仍需用户明确选择。
- 重复点击当前已选中的视频不会重置分镜就绪状态、未保存改动或页面步骤。分镜已经保存且无未保存修改时，第二、三步无需再次点击视频文件名即可进入。
- Playwright 覆盖无 reference 进入、刷新、重复点击及未保存改动保护。恢复可回退本次 Git 提交并重建前端；无数据库迁移。

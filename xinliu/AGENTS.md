# 心流开发约定

- 本目录 `xinliu/` 是当前开发根。前端在 `outputs/production-workbench/`，后端在 `backend/`，构建/启动/测试在 `work/`。仓库根目录是历史原型，不是最新版。
- 新对话先读 `outputs/心流_产品全景与开发交接_20261111.md`，核对当前代码和服务状态，不重新完整访谈或假装真实供应商已经联调。
- 前端原则：cut taglines, helper text and secondary labels. If a screen needs them to make sense, fix the layout. 用任务对象、布局、状态和明确操作说明页面，少口号与重复说明。
- 不机械隐藏全部文本。字段名、单位、来源/示例、权限、错误恢复、未配置和费用授权必须准确保留；风险在操作前呈现。
- 保留B端中性色、深橙主操作、可读中文、小圆角、紧凑列表、渐进展开与焦点。丰富度放在商品/样片/镜头/成片，不加AI装饰。
- 客户管理交付项目，员工处理当前待办，系统调度生成任务。重试不是新作品，下载不是客户采用。
- 不清空浏览器storage或 `backend/data`，不上传 `.env.local`、`provider.local.json`、客户素材、浏览器档案、日志或导出包。
- 后续所有敏感凭据按服务放入本地 `xx.env` 或现有 `.env.*` 文件，先确认Git/Docker忽略并设0600权限；仅提交无真实值的example模板。新增文件显式接入后端加载，不将凭据写进代码、前端、日志或交付包。
- 未配置供应商不伪装真实出片；真实识别、文本、视频都可能收费，需明确确认；未知不自动重发。
- 沿用栈，小范围增量修改。前端改动运行 `node work/build-production.cjs`，维护离线文件；使用已有模拟和浏览器验证，不消耗真实模型积分。
- Git提交、推送和生产部署按用户授权，正常提交不强推；设计/接口/环境变更同步交接文档。

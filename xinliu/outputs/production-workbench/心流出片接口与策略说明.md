# 心流：出片联调与独立策略

本轮将产品名改为“心流”，补齐品类与漫剧预览，新增可运行的Node.js后端与页面出片入口。真实供应商尚未提供正式接口和密钥，本轮没有调用Seedance，没有生成新的AI视频或消耗真实积分。

## 一、完成了什么

- 食品、家居、3C、宠物、漫剧使用五张原创SVG示意封面，不再用无关服饰图片填充。标为配方示例，不能作为商品证据或模型效果。
- 真实用户未上传素材、无音频、无授权角色的位置仍保持上传状态，不能为了“填图”伪造客户资产。
- 所有现有43种拍法均有不同的拍法指令，与七个品类、细类、平台、八种开场及功能策略组合。共享的是安全与商品事实规则，不是所有视频共用一段泛化Prompt。
- 输出分为图片理解Prompt、编导Prompt、视频Prompt和负面约束。编导介入程度影响方案调整范围。不同能力可独立请求供应商和计价。
- 场景变体自动选用scene策略；参考改编选用reference策略；动作迁移需显式选择motion，不用普通图生视频伪装。
- 新增“制作能力与独立策略”设置，包括目标人物、动作源视频、时段、迁移范围和接触关系。动作视频不足、时段无效、供应商未声明支持时会拦截。
- 图片识别/文本编导为自选模型环节，执行前也要确认报价。结果作为候选人工采纳，识别默认不作为宣传事实；新编导方案需要重新确认。
- 页面提供“准备视频出片”：素材上传/引用 → 输入快照 → 配置报价 → 费用确认 → 供应商调用 → 手动查单 → 转存结果 → 带回对应作品审片。
- 本地数据和媒体仍保留；新后端任务、输入快照、文件、来源Hash与预算预留保存在服务器私有数据目录，不依赖浏览器保活。

## 三、接口职责

| 接口 | 请求方法 | 用途 | 是否发起生成 |
| --- | --- | --- | --- |
| `/api/session` | POST | 带`X-Xinliu-Local: 1`，取得HttpOnly Cookie与csrf | 否 |
| `/api/config` | GET | 非敏感能力与报价摘要 | 否 |
| `/api/strategies` | GET | 独立策略目录 | 否 |
| `/api/prompts/compile` | POST | 编译方案的vision/director/videoPrompt | 否 |
| `/api/assets` | POST | 按clientId存文件或公网URL，返回assetId | 否 |
| `/api/tasks` | POST | kind为vision/text/video，保存输入与幂等键 | 否 |
| `/api/tasks?clientId=...` | GET | 查客户范围内后端任务 | 否 |
| `/api/tasks/{id}?clientId=...` | GET | 查某条任务 | 否 |
| `/api/tasks/{id}/quote` | POST | 校验素材、能力和配置报价 | 否 |
| `/api/tasks/{id}/submit` | POST | 明确报价及预算授权后执行一次调用 | 是，可能收费 |
| `/api/tasks/{id}/refresh` | POST | 查询已有视频任务，不重新生成 | 不发起新生成，查单成本仍需供应商确认 |
| `/api/tasks/{id}/result?clientId=...` | GET | 读取已转存的MP4/WebM，支持Range | 否 |

POST需带`X-Xinliu-CSRF`。任务输入需要clientId、workId、campaignId、kind、input、assets与idempotencyKey。资产职责支持product_image、character_image、garment_image、reference_video、motion_video、voice_audio。已选人物图随出片提交；已选服装和真人音频独立引用需供应商明确声明supportsGarmentReference、supportsAudioReference支持，否则报价前拦截，不只靠文字保证效果。

建立任务不是生成授权；创建成功只进入draft。quote是服务器配置估价，有效期五分钟，不是已核实官方价格。submit必须提交quoteId、authorized=true、acceptedCredits及budgetLimit。估价未知、能力不支持、预算不足均拒绝。

## 四、供应商配置

1. 复制项目内`backend/provider.example.json`到`backend/provider.local.json`。
2. 填你的真实模型ID、供应商baseUrl、创建任务路径、查单路径、状态/结果字段映射、支持的能力与规格，以及可核对的估价。
3. 在`backend/.env.local`中设置密钥，或在启动终端设置环境变量。模板为`backend/.env.example`。不要将真实Key贴到聊天或浏览器输入框。
4. 使用`outputs/重启心流服务.cmd`重启本项目服务。仅停止命令行精确匹配的项目预览进程，不清空数据或停止其他应用。
5. 打开“团队与费用 → 出片API → 检查接口状态”，先确认配置状态，再用真实商品素材进行一次小规模测试。

使用Node.js 22+；当前环境为Node.js24，无需额外npm依赖。服务只允许绑定127.0.0.1/localhost/::1，不可以直接暴露公网。

**关键：xinliu-bridge 是心流自己的适配契约，不是宣称存在的Seedance官方路径。**

当前视频请求默认结构：

```json
{
  "model": "供应商真实模型ID",
  "client_task_id": "心流任务ID",
  "capability": "commerce",
  "prompt": "确认过的独立策略Prompt",
  "negative_prompt": "本品类风险",
  "duration": 15,
  "aspect_ratio": "9:16",
  "resolution": "1080p",
  "assets": [
    { "role": "product_image", "url": "授权公网HTTPS或受支持的data URI" }
  ],
  "motion": null
}
```

如果你的供应商字段不同，可在配置中使用`requestTemplate`映射，或另写专用适配器：

```json
{
  "requestTemplate": {
    "model": "{{model}}",
    "prompt": "{{prompt}}",
    "duration": "{{duration}}",
    "references": "{{assets}}"
  }
}
```

模板只支持固定占位符替换，不执行代码。返回值可配置idPath/statusPath/resultPath以及成功/失败/运行状态枚举。提供正式文档后再决定采用字段映射还是专用SDK，不猜“Seedance2.5”的实际模型标识或协议。

视觉与文本支持配置为openai-chat兼容协议，不代表所有供应商都兼容。配置创建路径、模型、环境Key后，分别验证返回结构。识别结果与编导方案不能自动成为视频生成授权。

## 五、素材访问

- 本地上传单文件16MB，后端保存私有文件；结果转存上限120MB。
- 外部模型无法访问`localhost`或浏览器blob URL，因此视频参考必须提供授权公网HTTPS链接，或后续增加正式对象存储适配。
- 图片只有在供应商配置`supportsImageDataUri:true`时才使用data URI，否则同样需要公网HTTPS URL。
- 不自动生成外部下载链接或暴露本机目录，不复制客户Cookie，不绕过供应商认证。
- 结果只从配置的allowedResultOrigins获取，不跟随重定向至任意域名；拦截回环、内网与保留地址。该措施不是完整的生产SSRF安全认证。
- 视频验证文件标识为MP4/WebM，并记录Hash。时长、分辨率、动作、口型和商品真实性仍需浏览器与人工审核，不把可下载当成合格广告。

## 六、任务与费用安全

- 同一幂等键同输入复用任务，不同输入返回409。
- 已提交状态先持久化，再发供应商请求。并发重复点击不会重复生成。
- 创建请求超时或返回格式不明时保持unknown，不能自动重发或声称已退款。
- 上游任务ID存在才允许查单；查询使用当时的供应商配置，避免后续改配置查错平台。
- 成功后结果转存；结果获取失败可以查单与重取，不重新生成。
- 本地会话CSRF与Host/Origin检查，密钥只读服务器环境，不返回到前端或写进任务JSON。
- 预算预留是本地测试控制，不等于官方实际扣费、积分钱包或账务结算。未知和未核对费用保留，生产版需对账/结算/退款服务。
- 后端仅单进程持久化，生产需要数据库、并发锁、真正的企业权限、队列与监控。演示角色及clientId分类不能当作正式多租户鉴权。

## 七、GitHub研究与取舍

实际只读阅读：

- [Wan2.2](https://github.com/Wan-Video/Wan2.2)：区分T2V、I2V、音频驱动与Wan-Animate；动作迁移/替换需要视频与人物图，示例还有pose、face、mask或background预处理。借鉴其条件分离，不下载权重，不在本机安装GPU模型，不宣称Seedance自动支持这些条件。
- [Prompt-Relay](https://github.com/GordonChen19/Prompt-Relay)：全局约束与按时间段的局部事件指令分离。它会改变模型推理中的注意力路由，不是写上时间码就自动得到同等时序控制。本轮只借鉴结构，不集成其模型代码或宣传指标。
- [火山引擎Python SDK](https://github.com/volcengine/volcengine-python-sdk)：分服务SDK、Endpoint、鉴权与超时需要按正式文档配置。没有根据SDK通用说明猜测视频模型URL。
- [Dify许可证](https://github.com/langgenius/dify/blob/main/LICENSE)：多租户服务及前端品牌有附加条件。本轮不复制Dify源码来运营多租户SaaS。

GitHub仓库元数据接口本轮遇到限流，没有编造星标数量。所有策略内容为结合客户电商流程独立编写；不能把GitHub研究结论当成已训练或已验证的模型品质。

## 九、真实出片前还需要你提供

1. 视频供应商正式接口文档，以及真实模型ID、创建/查单URL。
2. 实际计价、失败/超时扣费、结果链接有效期和上游幂等规则。
3. 商品图片、人物图片、动作视频的格式、时长与数量限制；是否支持data URI、音频与motion条件。
4. 允许结果下载的存储域名、素材上传或对象存储方案。
5. 测试Key在本地服务器环境设置；给一个明确的小额测试上限后，再执行第一条真实生成。

这些缺口未补齐前，只做接口与模拟验证，不声称已经进入真实视频生成成功状态。“心流”按用户要求使用，本轮没有做商标或同名排查。

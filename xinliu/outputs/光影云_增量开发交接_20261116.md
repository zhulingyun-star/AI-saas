客户管理交付项目，员工处理当前待办，系统调度生成任务。作品不是模型调用，重试不新增作品，下载不是客户采用。

## 4. 知识与低成本制作路径

### 人工评价提炼

1. 上传或使用已有素材，记录好/差与具体镜头原因。
2. 选择1–50条已评价素材，按品类整理去重。
3. 整理结果进入原有“经验与规则”的知识草稿，保留来源素材与打标快照。
4. 人工核对来源、品类、内容和有效期，发布。
5. 用户明确选用某一版本，进入当前制作的固定知识快照。

打标不直接、全客户、永久地追加到所有Prompt。更新知识不静默改变旧方案，停用规则对新提交的约束沿用现有护栏。

### 视频AI提炼

1. 选择1–5条已评价视频；检查服务端vision供应商。
2. 核对处理授权，上传真实本地文件。
3. 为每条保存任务与准备报价，不调用模型。
4. 用户再明确确认总估价和本次费用授权，逐条调用。
5. 成功结果保存知识草稿；不完整/失败/未知停止后续，不自动重发。
6. 素材提炼的“查看后端任务”可核对已有任务；不会按一次按钮就批量自动训练。

“越用越好”当前是可审查的知识沉淀和显式版本复用，不是微调模型或自动训练保证。

### 热点表达

有当前草稿、品类匹配、未过期才能选用。选用前保存方案快照，表达进入当前方案备注，不替换商品价格/功效/实拍依据；修改后重新确认。来源和版本随方案保留，不要求用户重新输入长Prompt。

## 5. 数据模型与兼容

仍使用原生HTML/CSS/JavaScript、现有浏览器state/IndexedDB和Node后端；最新远端后端已使用H2，不能拿旧JSON服务覆盖。

- `state.teams` / `state.activeTeam`：分组、成员、可见客户、计划预算。
- `client.assets[].mark/markReason/labelHistory/directorId/markedBy/markedAt/markedTeamId`：评价与可追溯记录。
- `client.assets[].sku/tags/productSpec/activityPrice/priceUntil`：资料，不自动作为已核实事实。
- 已有SKU或已关联事实/作品的商品不能通过评价表单直接换SKU；新增商品素材再沿用原有换商品流程，避免旧依据与旧作品被静默改写。
- `client.labelEvents`：打标事件；`state.collaboration.notifications`仍为原通知存储。
- `client.hotspots`：当前客户热点；制作配置中的 `hotspotSnapshot` 固定所选版本。
- `client.knowledge`：沿用草稿/发布/停用、版本、来源和显式选用机制。
- 新模型任务输入 `input.config.teamId`：创建时冻结归属；接口返回 `task.teamId`，旧任务为null。不从当前团队反推历史费用。

现有客户共用同一个资料池时，团队依其客户范围查看资料；不是同客户下的项目/资产/知识硬隔离。新增团队不是新租户。

外部客户仍只查看明确分享给自己的固定交付版本，不继承员工当前团队筛选。健康接口的历史name字段保留“心流”以兼容原契约；前端和接口说明品牌改为光影云，存储键与URL未整体改名。

没有创建新的支付、钱包、充值、退款或订阅功能。计划预算和任务估价都不能宣传成供应商实际扣费上限。

## 6. 视频理解接口

继续用 `/api/assets`、`/api/tasks`、`/quote`、`/submit`。任务kind为vision，config.videoAnalysis为true，素材职责为reference_video。

仅gemini-content协议、显式 `supportsVideoDataUri:true` 接受服务器生成的视频inline_data。必须有已上传本地文件，硬上限16MB，可通过maxInlineVideoBytes降低。不接受blob链接或任意公网URL冒充Gemini File API的fileUri。

Yunxin使用 `YUNXIN_VIDEO_ANALYSIS_INLINE=true` 显式启用，默认false。沿用服务器vision密钥变量与估价；不会从浏览器localStorage读取Key，也不自动切换供应商或借用其他用途的Key。

模型ID、输入格式、限额、实际价格、内容合规和模型权限都需供应商真实联调。当前只完成本地模拟协议与交互，不代表该渠道已经真实分析视频。

普通视频生成的参考素材公网URL规则不变；inline仅新增在vision视频理解，不把动作迁移描述成已经真实生成验证。

## 9. 与附件的有意差异

- 不照抄“use strict导致模块隔离”的解释：当前是按顺序加载的classic scripts，严格模式本身不会建立模块作用域。不追加错误的window导出，保留已有渲染时机。
- 不在localStorage保存Gemini Key，不把普通公网URL或blob传作Gemini File API地址。
- 不把未审核打标原因直接永久附加到所有Prompt；先草稿、核对发布，再显式选用。
- 不把已上传资产总数写为已生成作品，不把评价比例写为投放转化效果。
- 不机械全文替换xinliu接口、存储键、历史文档和路径，避免改名损坏兼容与原浏览器数据。
- 原有UI质检入口默认并未挂载，不为附件里的修复描述制造新的改动。

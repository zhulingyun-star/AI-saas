# 电商内容组生产台：业务流与能力边界

本次交付是能实际上传、编排、导出和管理产单的本地前端软件；不是已接入官方视频模型的线上 SaaS。真实视频生成需要用户已有供应商的服务协议和凭据；页面明确展示未连接状态，不用演示成功替代接口返回。

## 本次先推翻了什么

1. 之前的页面过于通用，商品与具体拍法不够突出；新版用竖屏素材预览、逐镜脚本和后期配置承接一条视频。
2. “默认少生成”不等于“选择少”。选择应该多且便宜；昂贵模型任务按条确认。品类选定后展示相关拍法、证据与镜头结构。
3. DP 的核心管理单位是批次和产单，不应每次在新建项目弹窗重复填写。批量页以 SKU × 拍法 × 钩子组合建任务，显示潜在组合、实际上限和预算；不自动提交视频生成。
4. 编导能力不是大量运镜术语或电影质感。试穿要看正侧背，口播要给商品插镜，教程要看清步骤，大促要校对真实福利，剪辑要保留可验证信息。
5. 模特、穿搭、声音不能是空入口。新版可以筛选/上传模特、上传分部位服装、保存搭配参考、播放真人口播，并把这些选择写入脚本配置与提示词。
6. 一份通用五镜模板不等于理解参考片。新版真实读取视频时长和抽帧，允许手工校对切点，再分别记录画面、台词、音效、花字与改编。自动 ASR/OCR/切镜尚待接入。
7. 上传文件只在资产库显示还不够。逐镜可选择实际图片或视频与片段起点，本地导出真正使用这些素材。

## 传统岗位到 AI 视频业务流

| 传统环节 | 内容组实际工作 | 软件承接 | 当前实现 |
| --- | --- | --- | --- |
| 接需求 | 确定客户、商品、SKU、平台、活动、目标数量与截止 | 客户空间、单条任务与批次 | 本地客户与任务；真实团队后台待接入 |
| 看参考与拆片 | 抄结构，不照抄未授权人物/品牌；记录钩子、切点、口播与字幕 | 视频播放、真实抽帧、镜头与声音说明、改编单 | 已可上传、播放、抽帧、手动分镜和导出 |
| 选内容打法 | 按品类决定口播、试穿、教程、细节、实拍混剪等 | 品类动态选项、制作路线、钩子/场景/语气 | 已实现，脚本由本地规则生成，尚非文本模型 |
| 脚本确认 | 钩子、事实、证据、镜头、台词与 CTA；主管审方向 | 逐镜脚本、锁定、对应素材与时间轴 | 已实现编辑、锁定、素材引用、JSON/SRT |
| 筹备拍摄 | 找模特、配衣服、选景、道具、光线、收集使用素材 | 模特库、服装分部位、搭配单、场景/机位/商品状态 | 已上传、筛选、保存与引用；换装和身份生成未接入 |
| 实拍 | 同一人物/场景连续拍多条，拍口播和产品 B-roll | AI 生成需要的参考图与明确动作；保留实拍片段补证据 | 真实本地媒体可用；新动作需视频模型 |
| 录音 | 主播同期声或旁白、语速、停顿、方言/口音 | 录音上传、试听、音色与语速选择 | 用户音频真实播放；系统试听明确标注；无克隆 |
| 粗剪 | 按脚本选镜、裁剪、拼接、插产品近景 | 每镜素材、片段起点、时间段和预览 | 可编排上传图片/视频并导出 WebM |
| 后期 | 字幕、花字、音乐、音效、价格/赠品与封面 | 后期独立于画面；字幕与口播校对 | 字幕、花字、CTA、本地录音混入；音乐/音效完整混音待增强 |
| 审片 | 商品没看清、画面不对、音画不同步、字幕挡商品 | 时间码意见、问题类别、退回与版本记录 | 已有审片意见和状态；真实多人协作待后台 |
| 交付投放 | 文件命名、版本、素材 ID、交付到客户 | 产单、版本、WebM、脚本/SRT和交付清单 | 本地真实文件与元数据可导出；MP4/剪映草稿待实现 |
| 数据迭代 | 看有效素材成本与表现，保留好的打法，控制变量 | CSV、SKU/产单关联、客户配方复用 | 真实 CSV 计算；千川授权和自动归因未接入 |

传统流程不会被“一次文生视频”完整替代。对 3C、食品、美妆测试等真实性要求高的画面，现有实拍与使用记录应作为证据；AI更适合补镜头和构建新场景。视频合成、字幕和声音需要独立工作流，避免生成模型同时承担所有职责。

## 面向 DP 的页面组织

- **工作台**：批次与下一步待办，不铺满增长装饰；空白客户先准备商品、人员与预设。
- **做一条素材**：商品资料 → 拍法与出镜 → 镜头脚本 → 后期声音 → 制作交付。右侧持续看实际素材和后期样式。
- **批量排产**：SKU、拍法、钩子多选；继承模特、搭配、声音和字幕；展示乘积与实际数量上限。
- **产单队列**：按状态筛选、分页、紧凑行高、选中分配、提交预算校验、版本唯一编号。大量生产靠组织和复用，不靠一次盲目生成。
- **商品与素材**：实际文件与职责管理，素材可分配到某一镜。
- **模特库**：性别、气质、场景、来源和授权记录；示例与客户资产区别标注。
- **服装搭配**：外套、上衣、下装、整身装、鞋履、配饰；同部位替换、整身与上下装互斥；免费保存拼图引用。
- **音色与口播**：真人音频优先；系统试听与真实克隆音色区别显示。
- **参考片拆解**：真实视频与抽帧、时间码、叙事职责、声音、花字和改编并列。
- **客户预设**：记录已确认选择，不默默假设学习成功；一套配方对应具体品类和目标。
- **审片交付**：时间码和问题类别；未提交任务没有视频不能被当成已交付。
- **投放数据**：真实报表口径，关联素材/产单；报表有数据才显示指标。

新客户低密度；日常工作台中密度；产单、素材与分镜较密但有分页、阶段和筛选。苹果可借鉴比例、排版、圆角层级和反馈精度，工作页面不采用大留白、玻璃面板或长入场。控件通常 5–6px 圆角、面板 7–10px，动作约 150–220ms；商品预览内的电商字幕可更直接醒目，软件本身保持安静。

## 实际已验证

浏览器完整操作包括：品类拍法选择 → 模特筛选/上传 → 服装上传与互斥 → 搭配保存 → 音频上传 → 修改/锁定脚本 → 后期字幕选择 → 保存预设 → 8 条批量产单 → 分页/分配/预算检查 → 真视频上传/抽帧 → 参考改编 → 实拍片段引用 → 真实 WebM 导出 → 时间码审片 → CSV统计 → 客户切换与刷新。

14 个页面在 1500、1024、768、390 宽度下检查横向溢出；操作中没有页面脚本错误。批量排产账本消费为零。导出了 `真实本地粗剪示例.webm`，包含现有素材和字幕；它不是 AI 生成画面，不展示为 Seedance 样例。详细结果见同目录 `验证记录.json`。

本地文件保存于 IndexedDB，数据保存于 localStorage；客户隔离是前端分区，不能替代线上多租户鉴权。角色、账户、支付、跨用户协作必须服务端实现。

## 真正上线必须接入

1. 供应商服务地址、实际模型参数、鉴权、任务查询/回调、错误与报价协议。官方 Key 不应暴露在浏览器。
2. 多租户数据与对象存储、媒体转码、任务队列、审计与预算冻结/结算/退款；多用户共同使用同一客户。
3. 多模态商品识别、参考片 ASR/OCR/切镜、结构化文本编导与评测。当前规则草稿不可冒充训练好的编导模型。
4. 视频合成的 MP4、音画对齐、音乐/音效轨道、镜头缓存与局部重做。模型不支持的功能应使用实拍/后期路线，不伪造能力。
5. 模特与声音授权确认，真实定妆与换装验证；不能把拼图当成已生成上身图。
6. 正式千川/第三方授权和素材 ID 映射。当前 CSV 可作为第一版入口。

易小剧形象库实际观察到 **225 位示例人物**、地区/性别/气质筛选、人物、服装与搭配页签。搭配页按帽子、围巾、外套、上衣、连身装、下装、袜子和鞋分组；显示保存后先做免费拼图，定妆图另行生成。没有点保存或付费生成。

现有复刻项目观察到 **5 镜真实切点**、帧范围与疑似追加切点、逐镜展开、台词、花字替换、音效、BGM、混音说明和商品露出占比。原先“易小剧只有粗略入口”的判断不成立，之前的原型拆解也不足。该复查是读取已有结果，未验证新的拆解准确率，也未消耗积分。

# 心流 React 前端

本目录是原有 React 全栈版本按 `xinliu/` 新交互改造后的应用，使用 Java 17 / Spring AI 后端。参考实现 `xinliu/` 保持独立。

```bash
# Node.js 20.19+
npm ci
npm run dev
```

访问 http://127.0.0.1:5173 ，开发账号 `admin` / `change-me-local`；先在 `../backend` 启动 Java 服务。生产构建 `npm run build`。Docker 部署命令见根 README 和 deploy/README.md。

## 交互与业务对象

主导航为项目与制作、内容制作、资源中心、客户知识、投放复盘、团队与费用。

- **交付项目**：负责人、截止、交付目标、需求和归档，项目内按阶段查看作品、勾选本页、批量分配责任人与截止。
- **作品**：原有 `projects` API 表示单条内容，保留历史数据；新交付项目使用 `campaigns` API，二者不混作一个计数。
- **任务**：真实粗剪或供应商占位记录独立存储。重复生成是同一作品的新版本，不增加项目交付数量。
- **我的待办**：当前登录账号作为默认责任人；系统处理中归入“等待系统”，团队作品可以看所有当前客户作品。
- **快捷制作**：商品/角色 → 方案确认 → 出片/审片。方案默认列出时间码、台词和可展开画面，单镜弹窗编辑，右侧查看实际素材编排。
- **样片广场**：9 个拍法结构示例，品类筛选、搜索、后端保存收藏、换入自己的商品。示例素材不进入客户资产，不自动提供商品事实或授权。
- **场景变体**：每次 1–3 条，保留商品、台词和镜头顺序，记录来源作品及版本；重置事实确认，创建后需重新核对，不自动生成。
- **单镜参考改编**：指定源切点与目标镜头，只替换该镜画面文案，保留台词、时长和实际素材，拒绝修改锁定镜头；源视频与时间码保存在作品配置。
- **真实保存冲突**：revision 冲突时保留本地编辑，允许读取服务端版本或另存作品副本。没有注入假冲突按钮。
- **审片交付**：下载实际 MP4/SRT；无实际文件不能交付，已交付版本仍按原任务快照保留。

分工联系人是责任记录，不是虚构的登录账号或角色权限。现有登录与客户所有者权限仍由 Java 服务校验，团队邀请和共享访问控制尚未实现。未配置的 AI 视频供应商不会发出请求；本地粗剪仍可使用。

## 数据兼容

新增 Flyway V2，不修改 V1、不清空开发库或媒体。原有作品自动建立 workflow 行，初始不属于交付项目，可以通过分工弹窗归入项目。分工会同步作品配置并递增 revision，防止旧编辑器静默覆盖新分配。

测试会创建验收数据，请在测试环境运行。浏览器脚本见 `tests/workflow.spec.ts`，需要 Java 服务与 FFmpeg。
